01

What we are building

The first version prioritizes dependable motion and learning over payload, speed, or autonomy.

HEX-01 is a 3-DOF-per-leg hexapod: six articulated legs, eighteen inexpensive positional servos, a light printed frame, and a microcontroller executing inverse kinematics and a statically stable tripod gait.
Body planSix legs, three rotary joints per leg
Actuation12 positional 180-degree and 6 positional 360-degree servos
LocomotionAlternating tripod gait
Local controlPico or ESP32 running the motion loop
Servo interfaceTwo addressable PCA9685 boards at 50 Hz
Later expansionPi-based teleoperation, sensing, and vision
02

System architecture

Keep timing-sensitive movement local. Add a Linux computer only when the walking platform is already reliable.

Build now

Motion controller

A Raspberry Pi Pico or ESP32 calculates foot trajectories, leg inverse kinematics, joint limits, and gait timing. It sends PWM values over I2C to both PCA9685 boards.

Add later

High-level computer

A Raspberry Pi can provide Wi-Fi control, telemetry, camera processing, navigation, and high-level commands such as velocity and turn rate. It does not generate individual servo pulses.

Power rule

Never power eighteen servos from a Pico, ESP32, Uno, or Raspberry Pi power pin. SG90 current varies widely by load and manufacturer; startup or stall events can reach several amps across the robot. Use a fused, regulated servo supply, substantial wiring, local bulk capacitance, and a common ground.

Bring-up rule

Test one unmounted servo first. Establish conservative pulse limits before installing horns, then center each joint mechanically. A nominal 500-2400 µs range may drive some SG90 clones into their hard stops.

Relaxing a servo

Set the PCA9685 channel's FULL_OFF bit to stop its PWM signal. A typical analog SG90 then stops holding position and can move freely. Never relax a load-bearing leg unless the chassis is supported; it will collapse or shift suddenly.

def relax_servo(self, channel):
    """Disable one PCA9685 output using the FULL_OFF bit."""
    reg = PCA9685_LED0_ON_L + 4 * channel
    self.i2c.writeto_mem(
        self.address, reg, bytes((0x00, 0x00, 0x00, 0x10))
    )
Stall detection

SG90s provide no position or fault feedback. A current sensor on the shared servo rail can detect a sustained overload, but cannot identify one stalled servo while many are moving. Treat it as system protection and telemetry, not closed-loop joint feedback.

06

Build sequence

Each stage has a visible pass condition. Do not advance while mechanics bind or the power rail is unstable.

  1. Bench powerVerify 5 V under load, common ground, both I2C addresses, and an emergency power disconnect.
  2. Single servoFind safe pulse limits and confirm PWM disable. Do this without a horn attached.
  3. Single legAssemble three joints, record direction/offset data, and command repeatable foot positions with IK.
  4. Six-leg bring-upCenter one joint at a time with the chassis elevated. Confirm channel-to-joint mapping.
  5. Static posesStand, crouch, translate, and rotate the body slowly without lifting feet.
  6. Tripod gaitAlternate three-leg support groups with low stride height and a wide stance.
  7. FeedbackAdd current monitoring, IMU attitude, foot-contact sensing, or obstacle ranging only as needed.
  8. High-level controlAdd the Raspberry Pi for remote commands, telemetry, vision, or autonomy.
07

Design limits

SG90s make this an educational platform. Their limitations define the chassis and gait.

Keep load paths short

Short legs, a low body, light batteries, and minimal payload reduce joint torque. Avoid long printed lever arms and side loading on servo output shafts.

Fail gently

Clamp every joint command, start with low gait speed, elevate the chassis during first motion, and keep a physical servo-power disconnect within reach.

Do not trust commanded position

A standard SG90 does not report its actual angle. It may be delayed, obstructed, unpowered, or stalled while software continues normally. Use conservative trajectories and mechanical clearance rather than assuming a command was completed.

Servo assignment tool

Install servo_mapper_pico.py on the Pico as main.py, serve this directory with python3 -m http.server 8000, then open http://localhost:8000/servo_mapper.html in Chrome or Edge. The mapper identifies physical outputs with a narrow wiggle and exports the completed 18-joint map as JSON.

Servo calibration

Open http://localhost:8000/servo_calibrator.html to find and capture each joint's safe minimum, neutral center, and maximum pulse. Raw entry has no hobby-servo range guard, and the slider window is adjustable; only the physical 0-19,995 µs PCA9685 frame applies. Saving produces version 3 of servo-map.json with per-joint limits that manual control enforces automatically.

Manual servo control

Open http://localhost:8000/servo_control.html to load servo-map.json and control mapped joints. Position mode follows each confirmed calibration envelope; commands are coalesced to avoid a serial backlog. Center all moves the 18 joints sequentially to reduce the current step, while Relax all disables every PWM output.

Current code status

pca9685_bringup.py initializes both PCA9685 boards unconditionally and loops over all 16 channels on each board. That is a 32-channel test, not an 18-servo test. Before connecting the complete robot, revise it to map exactly 18 named joints and only command channels that are physically populated.
